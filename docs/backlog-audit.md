## Proposed batches

Batches run in parallel because their path globs are disjoint; work inside a batch is serial (same files). Shared edit points to expect: `internal/cli/root.go` (the AddCommand line) and `internal/config/config.go`. Whoever adds a command or config key rebases onto the other; both are one-line edits. `go.mod`/`go.sum` are merge-train serial files.

### Batch 1: merge train completion (serial inside; owns `internal/app/train*.go`, `internal/app/stack*.go`, `internal/gitx/rebase.go`, `internal/config/config.go`)
Order: #28 regen (adds `regen` config key) → #30 escalate after 2 attempts → #25 reorder/hold → #26 auto-rebase → #52 wire clustering into stacks. Then #31 pre-rebase and #29 structural merge (spike, doc-only plus `internal/gitx/merge*.go`). All touch `app/train.go`, so serialize.

### Batch 2: planner pipeline (owns `internal/planner/**`, new `internal/cli/plan.go`, `internal/app/ticket.go`)
Order: #8 planner call and schema → #7 epic sources (`gh:`) → #10 plan review/approve → #11 push as issues. Disjoint from batch 1 apart from the AddCommand line.

### Batch 3: adapters and MCP completion (owns `internal/agent/**`, `internal/mcpserver/**`, `internal/usage/parse.go`)
Order: #15 Adapter interface → #16 Codex/Grok adapters; #22 `brief` and `ask_owner` plus spawn depth/fan-out caps can run in parallel with #15 only if split across `mcpserver` and `agent` owners, otherwise after.

### Batch 4: TUI (single stream; owns `internal/tui/**`, `internal/narrator/**`, `internal/cli/status.go`, `internal/tmux/**`)
Order: #33 view router → #34 control view → #41 usage graph → #43 ask narrator → #37 `brief` pane + `status --tmux` + #14 → #36 merge view → #35 plan view (after batch 2). `tui.go` is one 1200-line file, so these must serialize; a second agent in `internal/tui` will conflict. Can start now alongside batches 1-3.

### Batch 5: reactor and dispatch (new `internal/reactor/**`, `internal/gitx/{watcher,state,delta,snapshot}*.go`, `internal/hook/hook.go`)
Order: #45 reactor → #47 forecaster → #49 holds → #50 checkpoints → #48 dispatcher → #51 TUI columns (joins batch 4's queue). Needs a design call on #5 first: the reactor wants a long-lived process. Start after batches 1-3, and #17/#27 (scheduler, barrier lane-pause, `internal/app/schedule.go`) belong here too.

### Batch 6: small leftovers (after batch 1 frees `config.go`)
#3 config keys, #4 store tables, #18 idle detection, #78 ADR rule (`internal/app/briefs.go`, `docs/adr/**`; can run any time, disjoint). **#5 daemon is an owner decision**: build it (L) or edit the architecture doc and close.
